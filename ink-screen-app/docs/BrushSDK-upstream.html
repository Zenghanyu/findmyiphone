BrushSDK iOS 集成说明

本文面向 iOS 接入方，按模块说明 BrushSDK 的接入方式、关键对象、页面入口和底层 API 调用。当前 Demo 已拆分为绑定设备、设备详情、直接刷图、图片管理和轮播、OTA。

Objective-C iOS 15+ BLE NFC XTDitherBleProtocol.xcframework

1. 交付内容

文件/目录说明
README.html当前集成说明文档。
BrushSDK 2026.8.21/BrushSDK.xcodeproj可运行 Demo 工程。

2. 工程接入

  1. 将 XTDitherBleProtocol.xcframework 添加到客户 Xcode 工程。
  2. 在 Target 的 Frameworks, Libraries, and Embedded Content 中将该动态库设置为 Embed & Sign。
  3. 如直接复用 Demo 封装，请把 BrushSDK/Core 下的 BLE、NFC、Support 相关文件加入客户工程。
  4. 如复用 Demo 页面，请把 MVC/Controller 中对应模块页面和依赖资源加入客户工程。
  5. 开启蓝牙、NFC、相册等系统能力和权限。

3. 核心对象

3.1 XTDeviceConfig

XTDeviceConfig 是所有模块共享的设备配置对象。绑定后必须保存，刷图、图片管理、OTA 都要传入同一个配置。

字段用途
brushType通信方式：brushWithBle、brushWithNfc、brushWithNfcAndBle。
screenWidth / screenHeight屏幕分辨率，图片需要按该尺寸裁剪或缩放。
screenColorCode / colorCount / colorDic屏幕颜色能力和设备颜色值映射。
scanType扫描方向：HorizontalType 横扫，VerticalType 竖扫。
screenSpecNumber屏幕规格序号，对应 1-9 号屏幕。
imageDataProcessType刷图数据处理类型。1.69 6色屏使用双芯片数据处理类型。
antiLostDevice / needsFindMyBrushModeSwitch防丢器标记和刷图前模式切换标记。1.69 6色防丢器刷图前需要先切换到刷图模式。
appID / uuID当前流程保存 MAC 地址。NFC 绑定和 BLE 绑定都只拿 MAC，后续由用户选择屏幕。
imageStorage / imageCount是否支持图片管理、图片槽位数量。
writeImageCount写图区数量。名片类设备可能使用双面写入接口。
supportCompress / compressAlgo设备压缩能力，SDK 在生成和发送数据时使用。

3.2 本地保存和读取

[XTDeviceConfig saveLocalCfg:deviceConfig];

XTDeviceConfig *deviceConfig = [XTDeviceConfig readLocalCfg];
if (!deviceConfig) {
    // 未绑定设备，请先进入绑定流程。
}

3.3 通信方式判断

switch (deviceConfig.brushType) {
    case brushWithBle:
        // 蓝牙刷图、蓝牙 OTA、蓝牙图片管理
        break;
    case brushWithNfc:
        // NFC 刷图；纯 NFC 不支持 OTA
        break;
    case brushWithNfcAndBle:
        // NFC 前置流程 + BLE 传输
        break;
}

4. 屏幕选择

绑定流程为：先通过 NFC 或 BLE 获取设备 MAC，再由用户选择 1-9 号屏幕。选择后按屏幕属性生成 XTDeviceConfig。

序号屏幕分辨率颜色扫描方向
11.54 4色200 x 200BWRYHorizontalType
21.54 4色 防丢器200 x 200BWRYHorizontalType
31.54 6色240 x 240BWRYGBHorizontalType
41.54 6色 防丢器240 x 240BWRYGBHorizontalType
51.69 6色400 x 400BWRYGBHorizontalType
61.69 6色 防丢器400 x 400BWRYGBHorizontalType
73.7 6色480 x 720BWRYGBVerticalType
85.89 6色680 x 960BWRYGBHorizontalType
94.0 4色528 x 768BWRYVerticalType
3.7 6色和 4.0 4色为竖扫，其余屏幕为横扫。客户如果自行实现屏幕选择页，需要保持该字段一致。
1.69 6色和 1.69 6色防丢器都是 400 x 400 圆形屏。界面预览按圆形裁切显示，但实际刷图数据仍使用完整 400 x 400 图像，不要把下发图裁成圆形。
1.69 6色防丢器需要在刷图前先切换刷图模式。复用 Demo 的 XTBleWriteHelper 时会自动处理：首次连接发送模式切换指令，设备主动断开后重新扫描、重连，再继续删除 Flash 和发送图片数据。自定义 BLE 流程时也需要保留这一步，并且不要把这次预期断开当作刷图失败。

4.1 根据 MAC 和屏幕生成设备配置

NSString *mac = @"A1B2C3D4E5F6";
NSInteger number = 8;
NSInteger width = 680;
NSInteger height = 960;
NSString *color = @"BWRYGB";
ScanType scanType = HorizontalType;

XTDeviceConfig *config = [XTTool getBindDeviceDataWithDeviceNumber:number
                                                               mac:mac
                                                       screenWidth:width
                                                      screenHeight:height
                                                             color:color
                                                  allowUnsupported:YES];
if (!config) {
    // 屏幕配置生成失败
    return;
}

config.brushType = brushWithBle;
config.appID = mac;
config.uuID = mac;
config.scanType = scanType;

[XTDeviceConfig saveLocalCfg:config];

5. 模块一：绑定设备

绑定模块只负责拿到 MAC 地址，然后弹出屏幕选择。屏幕选择完成后保存 XTDeviceConfig。

5.1 NFC 绑定

@interface YourViewController () <NFCHelperDelegate>
@end

NFCHelper *nfc = [NFCHelper shareInstance];
nfc.delegate = self;
[nfc getDeviceConfig:@"请靠近设备" isNeedScanTip:YES];
- (void)NfcReadConfigComplete:(XTDeviceConfig *)config {
    if (!config) {
        return;
    }

    NSString *mac = config.uuID.length > 0 ? config.uuID : config.appID;
    // 当前版本：NFC 只使用 MAC，后续弹出 1-9 号屏幕选择。
    [self showScreenPickerWithMac:mac brushType:config.brushType];
}

- (void)errCallBack:(NSString *)errMsg {
    // NFC 读取失败，可提示 errMsg。
}

5.2 BLE 绑定页面

如复用 Demo 页面，直接 push XTBleBindViewController。该页面会扫描附近设备，按信号排序，并过滤异常 RSSI。

@interface YourViewController () <XTBleBindViewControllerDelegate>
@end

XTBleBindViewController *vc = [[XTBleBindViewController alloc] init];
vc.delegate = self;
[self.navigationController pushViewController:vc animated:YES];
- (void)backBindMac:(NSString *)mac {
    if (mac.length == 0) {
        return;
    }

    // 当前版本：BLE 绑定页只返回 MAC，后续弹出 1-9 号屏幕选择。
    [self showScreenPickerWithMac:mac brushType:brushWithBle];
}

5.3 自定义 BLE 扫描列表

[[XTBleWriteHelper shareInstance] scanAvailableDevicesWithUpdate:^(XTBleScannedDevice *device) {
    NSLog(@"mac=%@ name=%@ rssi=%@", device.mac, device.deviceName, device.rssi);
    // device.supported 表示 SDK 是否识别该设备。
    // 当前绑定业务仍建议只取 device.mac，然后让用户选择屏幕。
} completion:^(NSArray<XTBleScannedDevice *> *devices, NSError *error) {
    if (error) {
        NSLog(@"scan error=%@", error.localizedDescription);
        return;
    }
    // 扫描结束，可刷新最终列表。
}];

7. 模块三：直接刷图

直接刷图模块包含图片预览、算法选择、导入按钮和悬浮日志。实际流程为：选择图片，裁剪/缩放到屏幕分辨率，调用图片转换，再按通信方式发送。

重要提示：如果刷图失败，请先重新绑定设备并重新选择屏幕后再试，避免分辨率、颜色或扫描方向与当前屏幕不匹配。

7.1 复用 Demo 刷图页

BrushScreenController *vc = [[BrushScreenController alloc] init];
vc.orignImage = inputImage;       // 已裁剪或缩放到设备分辨率
vc.deviceConfig = deviceConfig;
[self.navigationController pushViewController:vc animated:YES];

7.2 图片转换

ALG_TYPE_DITHER 为抖点算法，ALG_TYPE_COLOR 为色阶算法。SDK 会根据设备颜色和分辨率处理图片。

UIImage *brushDataImage = nil;
UIImage *displayImage = nil;
NSData *nfcDirectData = [XTImageDitherUtils convertToUploadData:sourceImage
                                                   previewImage:&brushDataImage
                                                 thresholdImage:&displayImage
                                                      deviceCfg:deviceConfig
                                                        algType:ALG_TYPE_DITHER];

if (!brushDataImage || !displayImage) {
    // 转换结果不完整：检查图片尺寸、设备配置、颜色类型。
    return;
}
previewImage 参数输出的是 RGB 取值图，必须用于后续生成 picData；thresholdImage 参数输出的是界面预览图，必须用于 UI 显示。两者不要互相兜底。NSData 主要用于纯 NFC 直接数据场景。
1.69 圆形屏有特殊处理：UI 显示仍使用正常转换得到的 thresholdImage，预览区域只做圆形遮罩；BLE 下发数据使用原图旋转 69.7 度后裁剪/缩放到 400 x 400，再按当前算法重新转换得到的 previewImage。也就是说显示图和下发取值图不是同一张图，但下发图仍必须保持 400 x 400 方图。

NSMutableArray *picData = [XTImageDitherUtils getUploadDataFromDitherImage:brushDataImage

8. 模块四：图片管理和轮播

图片管理适用于支持图片存储能力的设备，入口包括图片选择、槽位写入、快速 NFC 发送、删除槽位和轮播设置。开发工程前需要确认设备固件是否支持该功能；固件不支持时接口不会成功。

8.6 快速 NFC 发送

快速 NFC 发送用于 BLE 设备的图片管理场景：先通过 NFC 触发设备快速广播，再延迟调用原 BLE 图片槽位写入接口。

@interface YourViewController () <NFCHelperDelegate>
@property (nonatomic, assign) BOOL pendingFastNFCWrite;
@property (nonatomic, strong) NSMutableArray *preparedUploadData;
@property (nonatomic, assign) NSInteger selectedIndex;
@end

- (void)fastNFCSendSelectedImage {
    if (deviceConfig.brushType != brushWithBle) {
        return;
    }

    NFCHelper *nfc = [NFCHelper shareInstance];
    if (nfc.isReading) {
        return;
    }

    self.pendingFastNFCWrite = YES;
    nfc.delegate = self;
    [nfc getDeviceConfig:@"请靠近设备" isNeedScanTip:NO];
}

- (void)NfcReadConfigComplete:(XTDeviceConfig *)config {
    if (!self.pendingFastNFCWrite) {
        return;
    }
    self.pendingFastNFCWrite = NO;

    dispatch_after(dispatch_time(DISPATCH_TIME_NOW, (int64_t)(2.5 * NSEC_PER_SEC)),
                   dispatch_get_main_queue(), ^{
        [self writeImageData:self.preparedUploadData imageIndex:self.selectedIndex];
    });
}

9. 模块五：OTA

OTA 模块用于选择 .bin 固件并下发。纯 BLE 设备走 XTBleWriteHelper，NFC+BLE 设备走 NFCHelper，纯 NFC 设备不支持 OTA。

9.1 复用 Demo OTA 页

XTOTAViewController *vc = [[XTOTAViewController alloc] initWithDeviceConfig:deviceConfig];
[self.navigationController pushViewController:vc animated:YES];

9.2 准备 OTA 数据

NSData *fileData = [NSData dataWithContentsOfURL:fileURL];
if (fileData.length == 0) {
    return;
}

NSMutableArray *otaData = [NSMutableArray arrayWithCapacity:fileData.length];
const unsigned char *bytes = fileData.bytes;
for (NSUInteger i = 0; i < fileData.length; i++) {
    [otaData addObject:@(bytes[i])];
}

9.3 BLE OTA

if (deviceConfig.brushType == brushWithBle) {
    [[XTBleWriteHelper shareInstance] importOTADataToDeviceWithOtaHexData:otaData
                                                             deviceConfig:deviceConfig
                                                                 sendSize:244];
}

9.4 NFC+BLE OTA

if (deviceConfig.brushType == brushWithNfcAndBle) {
    [[NFCHelper shareInstance] importOTAToDevice:@"OTA"
                                      imageData:fileData
                                    imageDataXT:otaData
                                      screenCfg:deviceConfig

11. 接入注意事项

  • 绑定后请统一保存 XTDeviceConfig，后续模块不要重新拼接分辨率、颜色和 MAC。
  • NFC 绑定和 BLE 绑定获取 MAC 后，屏幕属性来自用户选择的 1-9 号屏幕。
  • 如刷图失败，请先重新绑定设备并重新选择屏幕后再试。
  • 刷图前必须把图片处理到设备分辨率，否则转换数据和设备显示可能不一致。
  • previewImage 是 RGB 取值图，必须作为 BLE 取数据图；thresholdImage 是界面预览图。不要互相兜底或反用。
  • 图片管理需要固件支持，开发工程前需要确认设备固件是否支持该功能。
  • 纯 NFC 设备不支持 OTA。
  • 同一时间只执行一个设备任务，避免 BLE 扫描、刷图、图片管理、OTA 并发。
  • 传输过程中如需中断，可调用 [[XTBleWriteHelper shareInstance] disconnectCurrentPeripherals] 断开当前 BLE 外设。
  • 如客户需要自定义 UI，可以只复用 Core 层 API；如需要快速验证，可以直接复用 Demo 中对应控制器。

The binding flow first obtains the device MAC through NFC or BLE, then asks the user to select one of the 1-9 screen options. After selection, build XTDeviceConfig from the selected screen attributes.

The 3.7 6-color screen and the 4.0 4-color screen use vertical scan. All other listed screens use horizontal scan.
The 1.69 6-color and 1.69 6-color anti-lost screens are 400 x 400 round screens. The UI preview is clipped with a circular mask, but the upload payload still uses the full 400 x 400 square image. Do not crop the upload image into a circle.
The 1.69 6-color anti-lost screen must switch to brush mode before image upload. When the Demo XTBleWriteHelper is reused, this is handled automatically: the first connection sends the mode-switch command, the device disconnects as expected, then the SDK scans and reconnects before deleting Flash and sending image data. If you implement a custom BLE flow, keep this step and do not treat the expected disconnect as a brushing failure.

7. Module 3: Direct Image Brushing

The direct brushing module includes image preview, algorithm selection, import actions, and floating logs. The flow is: select an image, crop or scale it to the screen resolution, convert the image, then send data according to the transfer type.

Important: If brushing fails, rebind the device, select the screen again, and retry to avoid resolution, color, or scan-direction mismatch.

7.1 Reuse the Demo Brush Page

BrushScreenController *vc = [[BrushScreenController alloc] init];
vc.orignImage = inputImage;       // Cropped or scaled to the device resolution
vc.deviceConfig = deviceConfig;
[self.navigationController pushViewController:vc animated:YES];

7.2 Image Conversion

ALG_TYPE_DITHER is the dithering algorithm. ALG_TYPE_COLOR is the color-level algorithm.

UIImage *brushDataImage = nil;
UIImage *displayImage = nil;
NSData *nfcDirectData = [XTImageDitherUtils convertToUploadData:sourceImage
                                                   previewImage:&brushDataImage
                                                 thresholdImage:&displayImage
                                                      deviceCfg:deviceConfig
                                                        algType:ALG_TYPE_DITHER];

if (!brushDataImage || !displayImage) {
    return;
}
The previewImage output is the RGB data image and must be used for building picData. The thresholdImage output is the UI preview image and must be used for display. Do not use one as a fallback for the other. The returned NSData is mainly for pure NFC direct-data flows.
The 1.69 round screen has special handling: the UI still displays the normal converted thresholdImage and applies only a circular preview mask; the BLE upload data uses the original image rotated by 69.7 degrees, then cropped/scaled to 400 x 400 and converted again with the current algorithm to produce the upload previewImage. The display image and upload data image are therefore different, while the upload image must remain a 400 x 400 square image.

11. Notes

  • Save XTDeviceConfig after binding and reuse it for all later modules.
  • After NFC or BLE binding obtains the MAC, screen attributes come from the selected 1-9 screen option.
  • If brushing fails, rebind the device, select the screen again, and retry.
  • Before brushing, process the image to match the device resolution.
  • previewImage is the RGB data image and must be used as the BLE data image. thresholdImage is the UI preview image. Do not use either as a fallback for the other.
  • Image storage requires firmware support. Confirm firmware support before starting project development.
  • Pure NFC devices do not support OTA.
  • Run only one device task at a time. Avoid concurrent BLE scan, brushing, image storage, and OTA operations.
  • Call [[XTBleWriteHelper shareInstance] disconnectCurrentPeripherals] to disconnect the current BLE peripheral when needed.
