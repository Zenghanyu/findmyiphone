## 适用范围

- 固定 240×240，共 57,600 个像素，有效区域 27×27mm；黑白红黄蓝绿六种色态。
- 本项目将 3 号与 4 号屏幕规格显式关联到 `HINK-T0154A10-A2`。这是根据本次提供的硬件做的项目配置，不是通过分辨率识别面板厂商。若更换面板，应在 `XTScreenSpecConfig.m` 修改或移除 `photoPanelProfile`。
- 当前启用条件：规格表包含此型号、实际尺寸为 240×240、颜色代码为 `60`、传输模式为普通 BLE。包括该模式下由 NFC 唤醒的快速 BLE 刷图。
- 普通导入和图片存储使用同一实现；其他规格、未关联型号的配置和纯 NFC / NFC 供电 BLE 模式保留 SDK 路径。此版不猜测纯 NFC 二进制格式；SDK 没有提供已确认的六色直接索引 NFC 入口。

## 处理链路

`原图裁剪 → 白底 sRGB → 抗混叠 Lanczos-3 到 240×240 → 有限 L* 结构增强 → 面板黑白点与色域映射 → 六色量化/蛇形扩散 → 单一索引图 → 显示预览与上传标记图`

1. **空间采样**沿用上一版可移植 C Lanczos-3，缩小时扩大支持域，并按像素覆盖区域限制振铃。仍在 sRGB 编码空间采样，以保留细线的感知覆盖对比。此版没有宣称使用线性光采样。硬件路径将通用 RGB 增强强度设为 0，避免两次锐化。面积采样作为实验对照保留，没有设成默认。
2. **结构增强**将采样图转到 D65 Lab，在目标像素尺度计算 3×3 `[1,2,1]²/16` 细节。强度 0.8，门控细节量 0.5～2 L*、局部范围 4～16 L*；每像素调整上限 `min(2 L*, 0.12 × 局部范围)`，a*/b* 不变。普通阶跃不产生超出邻域的新极值；由四对相反方向邻居识别细线/脊线，允许最多 1.5 L* 的有限极值扩展。平坦区与低幅中性噪声不增强。
3. **明暗映射**将源 sRGB 黑白点映射到面板的实际黑白点。使用显式的对角仿射 XYZ 模型：`K + (sourceXYZ / D65) × (W − K)`。它是首版媒体相对映射，不是精确光谱反射模型。
4. **可达色域**在线性 XYZ 中，把目标投影到六色色态的凸包，表示可实现的空间面积混色。距离为 `ΔX² + 2ΔY² + ΔZ²`。枚举至多四个顶点的单纯形，避免对 XYZ 各通道独立裁剪造成不可达目标；用独立 SciPy 约束优化验证投影。
5. **颜色选择**在 Lab 中按 `1.6ΔL² + Δa² + Δb²` 选色，提高亮度轮廓的权重。源色度 C*<4 的近中性区域只用黑白，抑制灰色照片中的蓝绿伪彩点。该阈值仍需在真机照片上复核。
6. **扩散**用蛇形 Floyd–Steinberg 基础权重，误差在线性 XYZ 中累计。导通率依据未抖点源图的 `sqrt(ΔL² + 0.25(Δa²+Δb²))`，在 8～24 的区间逐步减少跨边权重，默认强度 0.55。有效邻居内重新分配权重，将误差更多沿轮廓传播；内部权重和保持 1，图像边界维持原核的缺邻居损失。单通道残差限于 ±0.25 XYZ，防止极端残差拖出长纹。C 端只保留两行扩散误差。
7. **色阶模式**使用同一面板模型，只执行近邻颜色选择，关闭误差扩散。

早期实验直接衰减跨边误差会改变局部明暗，现已改为沿有效邻居重新分配。未使用 0.85 的强边缘保护默认值；强度扫描与保守选择见 `line_diagnostics.json`。所有阈值是本地对照选定的首版参数，不代表厂家推荐值。

## 预览与传输

- 一次量化得到 57,600 个合法索引，只允许 `{0,1,2,3,5,6}`，没有第七色、灰阶状态或额外像素。
- 显示预览把这些索引映射到标称 Lab 转换的 sRGB。它受白点假设、sRGB 色域和显示器影响，不是墨水屏实拍。
- 传输图把同一索引映射为现有精确 RGB 标记：黑 `(0,0,0)`、白 `(255,255,255)`、黄 `(255,255,0)`、红 `(255,0,0)`、蓝 `(0,0,255)`、绿 `(0,255,0)`。
- UIKit 图像以现有读图函数要求的 BGRA 存储；上传标记图按配置执行水平/垂直镜像，显示预览保持源图方向。
- `XTImageDitherUtils` 对此路径直接返回两幅图，BLE 不需要的 NFC 二进制返回 nil；通过已有 `getUploadDataFromDitherImage` 取索引，沿用扫描、分包、压缩与 BLE 写屏代码。**不再送入 SDK 二次抖点。**
- 从同一索引图派生的预览和传输只在颜色表现及配置镜像上不同。物理预览绝不能进入精确 RGB 取数，否则可能被旧函数当成黑色。

## 代码与复现

App 新增 `Core/Support/ImageDither/XTInkPhotoCore.h/.c` 和 `XTInkPhotoProcessor.h/.m`。前者为实际跨平台核心，后者处理 UIKit/sRGB/BGRA 边界。修改 `XTPhotoResampler` 以支持关闭通用增强，修改直接刷图和图片存储入口，修改屏幕规格关联及量化分流。

Python 原型为 `hink_model.py`，不调用 App 核心；Numba 仅加速独立参考扩散循环。测试用 ctypes 调用实际 App 的 C 源码。所有样例来自本机 scikit-image，未下载用户照片。

```powershell
$env:OPENBLAS_NUM_THREADS='1'
python tools/image_resampling/test_native.py
python tools/image_resampling/test_hink.py
python tools/image_resampling/experiment_hink.py
# 可替换为自己的本地照片；实验输出放到独立目录：
python tools/image_resampling/experiment_hink.py --input 'D:/photos/example.jpg' --output tools/image_resampling/results/my_hink_photo
```

依赖见 `requirements.txt`。本地 Zig 仅编译 Windows 测试 DLL，不是 iOS 构建工具或 App 运行依赖。新 C/ObjC 文件在 Xcode 同步源码目录中，不需手改传统 Sources 列表。

## 验证与取舍

- 原通用缩图的 21 项回归检查通过，涵盖 EXIF/旋转、6 种尺寸、抗混叠与受限增强。
- 新核心的颜色准备、色域投影、扩散、精确标记、物理预览、4 种镜像组合、行填充、非法参数、近中性噪声、色阶模式与细线质量检查见 `results/hink240/native_tests.json`。
- 四张照片的 Python/C 六色索引逐像素一致。随机准备阶段的最大浮点差约 `5e-14`；测试不只比较两套 Python 实现。
- 本机 240×240 硬件转换单次约 0.03 秒，约 3MB 核心临时存储；不包括原图裁剪/缩图，不代表 iPhone 性能。
- 四张照片与细线图的最终六色对照位于 `results/hink240/index.html`。列包含理想 RGB 色板参考、标称色板普通扩散、面积采样加边缘保护、选定的 Lanczos 加 L* 增强与边缘保护。**两种参考量化都不是闭源 SDK 的复现**。
- 指标用统一的 1px 高斯观察尺度比较最终 XYZ 混色与映射后的目标，记录 ΔE76。这个高斯不是硬件 MTF，ΔE 不是细节保留率。选定方案相对于同色板普通扩散有小幅色调误差代价，不能声称所有照片指标都提高。
- 白底细线诊断覆盖 0.5/1/2 目标像素宽度、两种斜率和四档扩散强度。选定方案在 1px 斜线上的走廊黑覆盖差由约 0.417 增至 0.432，平均位置误差由约 0.157px 到 0.150px；这只是特定合成图的诊断。0.5px 细线仍会断续，部分相位的位置误差略增，没有承诺恢复超出 240×240 网格的信息。
