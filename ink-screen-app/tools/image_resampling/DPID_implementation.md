# 激进 DPID 降采样试验与 App 接入

2026-10-23，Windows。本轮针对“在降采样时就保护局部对比度，先激进、少限制纹理增强”的要求实现。没有编译或运行 iOS App，没有向实屏传图。

## 当前默认链路

`原图裁剪 / 居中填充 → sRGB 原像素 → DPID 风格对比度自适应采样到 240×240 → 标称面板 Lab/XYZ 明暗与色域映射 → 六色量化和边缘扩散 → 同一索引图生成预览与上传`

在本项目 3/4 号 HINK 六色屏的普通 BLE 路径启用，包括直接导入和图片存储。仍用此前的型号关联和传输门控，其他规格与 NFC 模式保持各自路径。关闭这条路径后续的 L* 增强，避免把采样效果和目标尺寸二次锐化叠加。

## 这版 DPID 怎么工作

这是 **DPID 逆双边加权思路的面积覆盖变体**，不是论文发布代码的逐像素复现。采用实际输出像素覆盖区域作为采样域，避免把相邻区域的颜色直接混进当前像素。

1. 根据输出像素与原图像素单元的几何重叠面积，求高精度 RGB 面积参考 `m`。非整数缩放也计算实际覆盖比例，不把源区域随意取整。
2. 在这些参考值上以 `[1,6,1]²/64` 做轻度空间平滑，得到局部参考 `g`。邻域参与了判断，但最终颜色仍由当前覆盖区域内的源像素组成。
3. 对每个源像素 `p` 计算颜色差 `d² = 0.2126(R−gR)² + 0.7152(G−gG)² + 0.0722(B−gB)²`，所有值在编码 sRGB 的 0～255 范围。
4. 逆双边权重为 `r = max(d², 4)^(λ/2)`。越偏离局部参考的源像素，权重越大。取当前覆盖区域的最小 `r`，将最大权重限制为它的 32 倍。
5. 以 `覆盖面积 × r` 为权重共同计算 RGB，再与普通面积参考混合：`输出 = 10% × m + 90% × 自适应结果`。三个通道共用一份权重，不分别挑通道极值。

当前激进参数：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| 对比度指数 λ | 1.5 | 明显提高稀少高对比细节的贡献 |
| 最大范围权重比 | 32 | 保留较大的增强空间 |
| 自适应混合 | 90% | 仅保留 10% 普通面积结果 |
| 最小颜色差 | 2/255 | 极低幅度噪声内不区别加权 |
| 后续 L* 锐化 | 0 | 增强发生在采样阶段 |

例如 4×4 源区域里 15 个像素为 240、1 个像素为 20，普通平均约为 226；在单输出像素的此测试中，激进 DPID 得到 104。这个刻意放大的变化展示了稀少暗细节如何在合并之前参与决策，不是“恢复了真实覆盖率”的证明。

这版没有用严格的纹理分类或连续性筛选阻止孤立高对比像素增强，符合先做激进试验的要求。允许纹理更粗、孤立噪点更明显、细线加宽和局部明暗变化；也可能增加高频纹理的混叠。正权重保证结果不越过当前源区域的 RGB 极值，但不保证感知画质对所有照片都提高。

如果范围权重相同，直接返回面积参考，避免浮点误差影响低幅噪声；8 位舍入对半整数使用微小数值容差。相同尺寸、放大及一轴放大的混合缩放，不执行自适应增强，退回未锐化的 Lanczos。

## 实现位置

- `ios/BrushSDK/Core/Support/ImageDither/XTPhotoResampleCore.h/.c`：新增 `XTPhotoDPIDResampleRGBA`，实际 App C 算法。使用 RGBA8、支持行填充，额外存储只保留目标大小的 double RGB 参考，不分配原图大小的浮点结构图。
- `XTPhotoResampler.h/.m`：新增 `resizeImageUsingDPID` 和 `aspectFillImageUsingDPID`；保留原有输入方向、白底 sRGB 和输出 BGRA 约定。
- `MainViewController.m`、`XTImageStorageViewController.m`：HINK 路径切换为上述新入口。采样仍在后台执行。
- `XTInkPhotoProcessor.m`：量化时将 `detailStrength` 设为 0，其余面板参数、六色索引、镜像、扫描与封包保持此前的实现。
- `tools/image_resampling/dpid.py`：独立 Python/Numba 原型；`test_dpid.py` 编译和运行的则是实际 App C 源码。

## 对照与验证

`results/dpid240/index.html` 包含本机四张照片和细线图，分别比较面积平均、上一版 Lanczos、温和 DPID、激进 DPID。每组同时提供 RGB 采样、最终六色、局部像素放大、标记图与索引数组。温和参数为 λ=0.75、权重比 16、自适应混合 65%，只是本地对照，没有设为当前 App 默认值。

`metrics.json` 的“相对面积平均变化”仅展示增强幅度，不是画质分数或信息保留率。六色仍采用厂家标称 Lab 和临时 D65/2° 假设，不是实测校色；这些对照也没有复现闭源 SDK。

新增 DPID 的 **22 项检查通过**，结果在 `results/dpid240/native_tests.json`：

- 随机输入、非整数比例、单轴、相同尺寸、放大和混合轴的 C/Python 对照。
- 用独立有理数面积积分验证关闭自适应后的非整数采样；验证手算的 15 亮 / 1 暗样例。
- 平坦纯色不变、低幅中性噪声不增强、均衡棋盘格抗混叠、没有越过源覆盖区域的颜色极值。
- 源缓冲区不改写、行填充不覆盖、非法参数拒绝。
- 四张照片的 DPID RGB 与最终六色索引均与独立 Python 模型逐像素一致。
- 最终六色的亚像素细线诊断：白底 0.25px 暗线附近走廊每行黑像素数，上一版约 0.438、激进版约 0.854。说明这一测试中的线条贡献增加，同时也意味着可能加粗，不能解释为信息恢复率。其余宽度结果保存在 `line_diagnostics.json`。
- 本机 12MP → 240×240 采样约 0.85 秒，包含测试缓冲区准备与复制，不代表 iPhone 性能。DPID 比原 Lanczos 更耗时；当前完整照片采样在后台执行。

同时运行通用缩图与硬件量化原有回归，分别为 21 项和 16 项。本轮合计 59 项检查；UIKit 方向、颜色管理、iOS 构建和实屏仍需 Mac/iPhone 验证。

## 本地复现

在仓库根目录执行，依赖沿用 `requirements.txt` 和本地 Zig：

```powershell
$env:OPENBLAS_NUM_THREADS='1'
python tools/image_resampling/test_dpid.py
python tools/image_resampling/experiment_dpid.py
python tools/image_resampling/experiment_dpid.py --input 'D:/photos/example.jpg' --output tools/image_resampling/results/my_dpid_photo
```

要回到温和风格，先用报告中的温和列对照；源代码的激进默认参数位于 `XTPhotoResampler.m`，Python 默认值位于 `dpid.py`。C API 参数显式传入，修改后应同步重跑对照与 C/Python 一致性检查。
