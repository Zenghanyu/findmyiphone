## 2026-10-12 旧版真机记录

设备：iPhone 15 Pro Max / iOS 26.5、Seeed XIAO ESP32S3 Sense。

### 已验证

| 功能 | 证据 |
| --- | --- |
| 系统 BLE HID 配对 | 开发板加密、绑定及 HID 订阅日志，用户实际连接 |
| 默认 3 秒拍照 | 实体 BOOT 短按，用户确认系统相机拍照 |
| App 修改延时 | App 保存 5 秒成功，离开 EasyFind 后打开系统相机，用户确认约 5 秒拍照 |
| 参数持久化 | 板端保存、重启和读取验证 |
| 前台反向找手机 | 实体 BOOT 长按，用户确认声音或震动及页面状态 |
| 锁屏后台接收 | 日志确认 `appState=2` 收到找手机事件，普通通知实测通过 |
| AlarmKit 后台调度 | 真机授权后，后台收到事件并成功创建 `scheduled` 闹钟，约 2 秒后进入 `alerting` |
| 系统闹钟与锁屏停止 | 用户确认锁屏响铃和停止；系统日志确认停止后闹钟被移除 |
| 静音和重复触发 | 用户确认静音下响铃，停止后再次按键仍可触发 |

### 软件验证

- 真机签名构建、签名完整性检查、安装与启动通过。
- 系统闹钟版本 4 项 UI 回归通过：未授权状态、关闭响铃后不触发、设置保存与重启保留、停止后再次触发。UI 测试使用模拟设备，不作为真实系统闹钟的证据。
- 固件主机协议测试涵盖报文、参数边界、忙状态和计时回绕等情况；构建方法见固件 README。

### 旧版实现边界

- 拍照由固件独立计时并发送 HID 音量键，系统相机需要已经打开；固件不会解锁或启动相机。
- 找手机需要 App 收到蓝牙事件。正常返回桌面与锁屏已验证，上划强退后不保证可用。
- iOS 26 起使用 AlarmKit，需独立闹钟授权；低版本使用原通知方式。一次只维护一个找手机闹钟，重复按键不排队。
- 专注模式、长时间锁屏、超距重连、手机重启、其他机型与 Android 未在本轮验收。
- 当前固件替换了开发板原录音程序；原 Flash 备份只保存在本机，不随仓库上传。

### 锁屏接收修复

系统已连接 HID 设备不代表 App 已建立自己的 CoreBluetooth 连接。对检索出的外设显式调用 `connect`，并将服务提升到 App 生命周期持有、在启动时恢复，解决了本机此前锁屏收不到事件的问题。闹钟调度只申请短时后台任务，响铃交给系统处理。
