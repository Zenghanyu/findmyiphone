# EasyFind 自拍杆固件协议草案 v0.1

日期：2026-10-12。状态：App 客户端与模拟设备已按本草案开发；XIAO ESP32S3 测试固件位于 `firmware/EasyFind-XIAO/`，已编译、烧录并通过板端串口配置读写和重启持久化检查。iPhone 15 Pro Max（iOS 26.5）的系统配对、默认 3 秒拍照、真机 App 保存 5 秒后离开 App 使用系统相机拍照，均已由用户确认。反向找手机前台通过；修复 App 自身连接及生命周期后，锁屏后台复测也通过，用户确认通知及声音或震动，日志确认后台收到事件并成功提交通知。长时间锁屏、超距重连及上划强退等场景未验收。以下自定义 UUID、操作码和能力位不能当作现有 FindMyTag 标签已经支持的协议，量产仍需固件厂商确认。

## 1. 产品行为

用户先在手机系统蓝牙中完成自拍杆配对和连接，再在 EasyFind“功能”窗口设置延时，将配置保存到自拍杆。日常使用时，用户打开手机系统相机，按自拍杆远程拍照按钮。设备独立倒计时，到时发送标准 HID 音量增加键，不依赖 EasyFind 在前台或后台运行。App 不负责扫描、选择或建立系统蓝牙配对。

- 延时范围为整数 0–30 秒；0 秒立即发送快门按键。
- 本草案的出厂延时为 3 秒，模拟设备采用同一默认值。
- 短按一次开始倒计时；倒计时中再次短按取消。
- 配置在设备断开配置连接、掉电和重启后保留；进行中的倒计时在重启后取消。
- 配置服务断开不应取消设备计时；HID 链路断开则取消待拍动作，重连后不得补发。
- 相机需已打开。HID 不负责解锁手机、自动打开相机或保证照片已保存。
- 自拍杆的找手机按钮通过配置服务主动上报 `PhoneFindRequested`。iOS 26 起，首次授权系统闹钟后，App 在收到事件时安排约 2 秒后的 AlarmKit 一次性闹钟，由系统响铃并提供锁屏停止操作；App 订阅系统状态并支持取消。iOS 26 以前保留前台提示音/震动和后台本地通知。

本阶段不包含连拍或 OTA。通知兼容路径受通知权限、静音及专注模式影响。系统闹钟需要单独的 AlarmKit 授权，不用通知权限代替；关闭并保存“允许响铃”后不创建闹钟。系统闹钟可以突破静音和专注模式，实际音量和提醒效果以真机设置与测试为准。所有路径都仍需要 App 收到 BLE 事件，不能承诺上划强退后可用。新版已安装，用户确认系统闹钟锁屏响铃、锁屏停止、静音下响铃以及停止后再次触发均成功；日志确认后台调度和约 2 秒后进入 `alerting`，停止后系统清除了该闹钟。专注模式、长时间锁屏等场景尚未单独验收。

## 2. 蓝牙结构

建议同一设备提供 **BLE HID over GATT Profile（HOGP）+ 独立自定义 GATT 配置服务**。普通 BLE HID 不必使用传统蓝牙 Classic。操作系统处理 HID；EasyFind 使用 CoreBluetooth 连接配置服务。二者并行使用、断开配置客户端后的 HID 行为必须在真实 iPhone 和 Android 手机验证。

| 服务/特征 | UUID | 用途 |
| --- | --- | --- |
| 标准 HID Service | `0x1812` | 操作系统接收遥控按键 |
| 自定义配置 Service | `AEBB1000-7F4A-4A38-8CF0-18D6BB28B273` | 已经由系统连接后供 App 读取和配置 |
| Command Characteristic | `AEBB1001-7F4A-4A38-8CF0-18D6BB28B273` | 手机→设备，Write with response |
| Response Characteristic | `AEBB1002-7F4A-4A38-8CF0-18D6BB28B273` | 设备→手机，Notify，提供 CCCD `0x2902` |

HID 服务按 HOGP 实现 HID Information、Report Map、HID Control Point、Input Report 和 Report Reference 等标准属性；不要直接向配置特征写“音量键码”代替 HID 报告。

推荐输入为 Consumer Page `0x0C` 的 Volume Increment `0xE9`。Report ID、位布局由固件 Report Map 定义。触发时发送按下报告，约 50 ms 后发送全释放报告，每次只发送一组，避免键卡住或连拍。手机相机是否把它映射为快门，需要按机型和相机 App 实测，部分 Android 相机需设置音量键功能。

配置写入、通知及 HID 输入需按 HOGP 和设备绑定策略保护，建议使用绑定后的加密连接。App 设置成功不代表已经完成系统 HID 配对，也不代表手机当前相机已打开。电量服务 `0x180F`、设备信息服务 `0x180A` 可在后续扩展。

本配置服务不使用现有 NI/UWB 服务 UUID，不复用其操作码，避免向现有标签发送未经定义的命令。

## 3. 报文格式

每次 ATT 写入或通知包含一条完整帧，最大 20 字节，兼容默认 ATT MTU。多字节整数使用小端。

| 偏移 | 长度 | 字段 | 定义 |
| --- | --- | --- | --- |
| 0 | 2 | Magic | 固定 `53 46`（十六进制） |
| 2 | 1 | Version | `01` |
| 3 | 1 | Opcode | 见后文 |
| 4 | 2 | Sequence | 请求非零；回复原样回显；主动事件为零 |
| 6 | 1 | Payload Length | 0–13 |
| 7 | N | Payload | 实际长度必须与头部一致 |

BLE 链路本身提供检错机制，此短帧不另加自定义 CRC。magic、版本、长度、操作码、参数范围仍须检查；格式错误或未知版本不执行写入。

### 状态码

| 数值 | 含义 |
| --- | --- |
| `00` | 成功 |
| `01` | 参数不合法 |
| `02` | 功能不支持 |
| `03` | 非易失存储提交失败 |
| `04` | 设备忙，例如正在倒计时 |

### 能力位

配置回复中的 `Capabilities`：bit 0 表示 HID 音量增加键，bit 1 表示非易失保存，bit 2 表示设备端计时，bit 3 表示找手机事件，其他位预留。App 仅在前三个能力均具备时启用远程拍照保存；支持完整功能的设备应报告 `0F`。

能力位报告的是固件能力，不是手机配对成功或相机拍照成功的证明。

## 4. 配置命令

| 操作码 | 方向 | 负载 |
| --- | --- | --- |
| `01` READ_CONFIG | 手机→设备 | 空 |
| `81` CONFIG_REPLY | 设备→手机 | `[status, persistedDelay, maximumDelay, capabilities]` |
| `02` SET_DELAY | 手机→设备 | `[requestedDelay]` |
| `82` DELAY_REPLY | 设备→手机 | `[status, persistedDelay]` |

`maximumDelay` 范围 1–30，`persistedDelay` 范围 0–maximumDelay。所有回复长度固定，不因失败状态省略字段；失败时回传之前保存的配置。

系统蓝牙连接可用后，App 通过 `retrieveConnectedPeripherals(withServices:)` 找到该服务，先订阅 Response，再发送 READ_CONFIG。App 读取的是设备已持久化的配置，不能把手机上次选择的值当作设备当前值。找不到系统已连接设备时，页面只提示用户返回系统蓝牙连接，不启动附近扫描。

写入过程：校验→原子提交非易失存储→更新运行配置→回复成功。存储提交失败则保留旧值并回复 `03`。ATT Write Response 只表示 BLE 属性写入完成，不是 Flash 保存确认。

App 只有收到本次 Sequence、正确回复类型、成功状态和一致延时回显后，才显示保存成功。一次只发一个配置请求，确认超时为 5 秒。超时后配置状态视为未知，断开配置连接并要求重新连接读取；不能假设设备仍是旧值，也不能假设新值已保存。

SET_DELAY 应具备幂等性：同一配置值无需反复写 Flash。同一连接中可缓存最近的事务结果，重复相同请求直接返回原结果；相同 Sequence 配不同内容应拒绝。不要未经确认地自动重发设置命令。

### 示例：设置 5 秒

事务号 `0x1234`，手机写入：

```text
53 46 01 02 34 12 01 05
```

设备成功保存后通知：

```text
53 46 01 82 34 12 02 00 05
```

若原延时为 3 秒，Flash 保存失败：

```text
53 46 01 82 34 12 02 03 03
```

读取配置，事务号 `0x0007`：

```text
请求：53 46 01 01 07 00 00
回复：53 46 01 81 07 00 04 00 05 1E 07
```

回复含义为保存延时 5 秒、最大延时 30 秒、支持三个基础能力。

## 5. 可选状态事件

事件用于 App 显示状态和处理反向找手机，不得作为设备倒计时或发送 HID 的必要条件。配置客户端未连接或未订阅时，仍执行设备自身逻辑；找手机按钮也可在配置客户端暂时断开时按产品策略重试通知。

Opcode 为 `E0`，Sequence 为 `0000`，负载为 `[event, remainingSeconds]`：

| Event | 定义 | Remaining |
| --- | --- | --- |
| `01` | 倒计时开始 | 初始剩余秒数 |
| `02` | 剩余时间变化 | 0–30 |
| `03` | HID 快门按键已发送 | 0 |
| `04` | 倒计时已取消 | 0 |
| `05` | `PhoneFindRequested`，找手机按钮被按下 | 0 |

事件 `03` 只表示已发送按键，不能证明相机拍照成功。事件 `05` 只请求手机提醒，App 不得把它当作快门命令。App 不得再收到事件 `03` 后自行延时或补发快门，否则会出现双重延时或重复拍照。

## 6. 固件状态机与验收

```text
待机
 ├─短按且 HID 就绪、延时 0 → 发送按下/释放 → 待机
 └─短按且 HID 就绪、延时 >0 → 设备倒计时
                                      ├─到时且 HID 仍就绪 → 按下/释放 → 待机
                                      └─再次短按、HID 断开或重启 → 取消 → 待机
```

使用非阻塞定时器和单调时钟，按键需消抖。倒计时期间 SET_DELAY 返回忙，已有配置不变。HID 未连接时不排队等待拍照；设备可用 LED 提示连接状态。

真实硬件验收至少覆盖：

1. iPhone 和 Android 分别在系统蓝牙完成 HID 配对；App 只读取系统已连接的配置服务，不提供第二次配对。
2. 即刻、3 秒、5 秒、10 秒及自定义 30 秒；每次恰好一组按下/释放。
3. 保存后退出 EasyFind、取消配置连接，打开系统相机，设备仍按保存值延时拍照。
4. 设备掉电重启后重新读取配置，延时一致；重启不会补发旧快门。
5. 未保存的 App 草稿不会改变设备行为。
6. 倒计时中再次短按取消；HID 断开或相机未打开时不产生延后补拍。
7. 保存失败、确认丢失、迟到回复、非法参数和旧事务号均不会让 App 错报成功。
8. 用户离开相机、锁屏或手机处于通话等状态时确认按键影响；记录兼容机型及相机设置。
9. 找手机按钮在 EasyFind 前台、后台和锁屏状态各触发一次；记录通知授权、声音、震动、专注模式和系统杀进程后的实际结果。

当前模拟器可验证客户端状态、报文处理和模拟配置持久化，不能验证射频通信、系统 HID 配对、真实拍照、硬件 Flash、设备功耗或 App 退出后的设备独立运行。
